创建与管理 API 密钥

API 密钥（API Key，也称令牌）用于授权应用调用模型。建议每个应用使用独立密钥，便于控制预算、定位用量和单独停用。

创建密钥

  1. 打开API 密钥，点击 创建 API 密钥。
  2. 填写便于识别的名称，例如“个人聊天”或“开发测试”。
  3. 选择可用分组，并设置符合用途的额度、有效期和模型范围。
  4. 保存后，使用 复制 API 密钥 或行菜单中的 复制密钥。
  5. 将完整密钥填入可信客户端的 API Key 字段，或保存在应用服务端的环境变量中。

密钥名称和隐藏后的星号不能用于调用。复制后检查首尾空格与换行；首次测试建议使用较小预算。

获取 API 地址

在同一页面点击 API 地址，复制适合当前网络的接入地址。是否需要追加 /v1，取决于客户端的协议配置，见客户端接入。

设置访问范围

设置 含义 使用建议
有效期 到期后不能继续调用 测试和临时用途设置较短期限
额度 该密钥允许消耗的预算 按应用分配；不会增加账户余额
模型限制 允许调用的模型范围 选择当前应用需要的模型
IP 限制 允许发起请求的来源地址 固定出口服务适合设置；代理和移动网络可能改变出口
分组 决定可用渠道及相关价格 与目标模型的可用分组一致

“无限额度”表示不设置该密钥自身的额度上限，账户余额和套餐限制仍然有效。

确认密钥可用

按照首次调用查询模型并发送一条短消息，然后在用量日志核对记录。仅能获取模型列表，还不足以证明模型可以正常生成内容。

密钥泄露怎么办

立即停用或删除旧密钥，创建新密钥并更新应用。随后检查异常调用记录，必要时联系支持核对。旧密钥停用不会撤销已经发生的调用。

完整密钥不应出现在截图、公开仓库、网页源码或支持工单中。“安全与访问”中的个人访问令牌 PAT 用于管理 API，普通聊天软件应使用本页创建的模型 API 密钥。
