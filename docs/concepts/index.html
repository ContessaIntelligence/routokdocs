模型 API 参考

接入前需要了解的概念

一次模型调用通常经过：你的应用 → RouTok（基于 New API）→ 模型服务商。先理解地址、密钥、模型和额度，接入时就更容易定位问题。

三种凭据

凭据 签发方 用途
上游 API Key 模型服务商 管理员配置渠道
模型 API 密钥 当前 New API 实例 应用调用聊天、图片等模型接口
个人访问令牌 PAT 当前 New API 实例 自动化调用管理 API，受 scope 和账号权限限制

浏览器登录凭据用于控制台会话，不应作为应用的长期 API Key。普通客户端使用本站的模型 API 密钥。

API 地址与完整路径

名称 示例 用在哪里
API 根地址 https://gateway.example.com 本指南的 NEW_API_BASE_URL
SDK 基础地址 https://gateway.example.com/v1 OpenAI SDK 的 base_url／baseURL
完整接口地址 https://gateway.example.com/v1/chat/completions 直接 HTTP 请求

部分软件会自动添加版本路径。请按客户端配置说明填写，避免重复出现 /v1/v1。

模型、渠道与分组

  • 模型 ID：请求中的模型标识，通常填写在 model 字段。以本站提供的 ID 为准。
  • 渠道：网站通往上游服务的配置，包含地址、凭据和支持的模型。
  • 分组：影响密钥可访问的渠道和价格。模型存在，但所选分组没有可用渠道时，仍无法调用。
  • 模型映射：管理员可把本站模型名映射为上游模型名或部署 ID。
  • 优先级与权重：网站用于选择渠道的配置，通常由管理员维护。

额度与 Token

额度是预算，Token 是用量，API Token 是凭据。 三者名称接近，含义不同。

账户余额、密钥额度、套餐限制和上游余额分别生效。某一层不足都可能阻止调用，排查时应结合具体错误，而不是只看账户余额。
