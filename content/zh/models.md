# 查询和选择模型

先按任务选择模型，再确认接口、分组和价格。模型广场适合浏览；模型列表 API 用于核对当前密钥可见的模型。

## 在模型广场选择

打开[模型广场](/pricing)，按名称、类型、供应商或分组筛选，查看模型详情并复制完整模型 ID。

![New API 模型广场示例，展示筛选、模型 ID、价格与接口信息](/images/models.zh-CN.jpg)

*① 按用途筛选，② 复制模型 ID，③ 核对计费单位与价格。截图为项目模拟配置，价格和可用模型不代表本站报价。*

| 使用目标 | 优先确认 |
| --- | --- |
| 普通聊天 | 文本质量、延迟、价格和上下文长度 |
| 图片理解 | 是否支持视觉输入及图片格式 |
| 工具调用 | 是否支持当前协议的工具定义和多轮调用 |
| 知识库检索 | 向量模型的维度；是否另需重排序模型 |
| 图片或视频生成 | 提交协议、参数范围、等待方式和计费单位 |

## 用密钥查询模型

先按[首次调用](/docs/quickstart#准备接入信息)设置环境变量。以下命令用于 Bash：

```bash
curl --fail-with-body "$NEW_API_BASE_URL/v1/models" \
  -H "Authorization: Bearer $NEW_API_KEY"
```

响应的 `data[].id` 是调用时使用的模型 ID。列表可见只表示凭据能够看到该模型，不代表所有接口和能力均可用。

## 参考排行榜

[排行榜](/rankings)展示统计范围内的模型使用趋势和服务商占比。排名可用于发现候选模型，最终仍应使用自己的代表性问题测试质量、延迟和费用。

## 模型不可用

依次核对：API 地址 → 完整模型 ID → 密钥模型限制 → 所选分组。仍提示没有可用渠道时，提供模型 ID、时间和脱敏错误，由支持人员检查渠道状态。

更换模型后，重新验证工具调用、输出格式、多模态和费用，不宜只修改名称就直接投入生产。
