# 调用失败排查

先保留 **发生时间、HTTP 状态码和脱敏错误信息**。按下表定位问题，通常比反复更换配置更快。

## 根据错误定位

| 现象 | 优先检查 | 后续处理 |
| --- | --- | --- |
| 401／未授权 | 密钥是否完整、有效，是否由本站签发 | 检查[密钥设置](/docs/keys) |
| 403／无权限 | 模型、IP、分组和账号权限 | 核对访问范围，必要时联系支持 |
| 404／接口不存在 | 地址是否重复 /v1、接口是否开放 | 对照[协议路径](/docs/protocols) |
| 400／参数错误 | 模型 ID、字段类型、参数支持情况 | 使用最小请求复测 |
| 413／请求过大 | 文件和请求体大小 | 减少内容，核对模型限制 |
| 429／触发限制 | 请求频率、并发、套餐或上游配额 | 根据错误内容查看[限制说明](/docs/limits) |
| 5xx／服务错误 | 网关、上游或代理是否暂时异常 | 保留请求标识，查询日志后再决定是否重试 |
| 没有可用渠道 | 模型 ID、密钥分组和模型范围 | 按[模型指南](/docs/models)检查 |
| 余额不足／额度不足 | 账户、密钥及套餐各自状态 | 依次核对[钱包](/docs/wallet)和密钥额度 |

状态码只是定位线索，具体原因以响应内容为准。

## 网页能用，软件不能用

1. 核对软件使用的是本站提供的 API 地址。
2. 确认填写的是模型 API 密钥，且没有多余空格。
3. 使用完整模型 ID，并核对密钥分组。
4. 去掉可选参数，发送一条短文本请求。
5. 检查客户端是否自动补充 `/v1`。

可以用[首次调用示例](/docs/quickstart)对照。命令行成功而软件失败时，重点检查客户端的地址拼接和参数。

## 流式输出集中在最后出现

使用[流式示例](/docs/streaming)对比。命令行正常时，检查软件读取与显示逻辑；各客户端都异常时，反馈给支持人员检查代理缓冲和网络链路。

## 超时后是否重新提交

先查询任务或日志。请求可能已到达上游，直接重发可能创建独立任务并产生额外费用。未获得任务 ID 时，也应保留时间和请求标识以便核对。

## 仍未解决

使用[反馈模板](/docs/support#提供排查信息)提交最小复现。保留服务端实际返回的 Request ID；完整密钥和私人内容请替换为 `REDACTED`。
