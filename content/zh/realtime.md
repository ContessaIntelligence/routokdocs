# 实时连接与 WebSocket

实时音频等双向交互可以使用 WebSocket。仅需要逐步显示文本时，优先采用[HTTP 流式响应](/docs/streaming)。

## 选择接口

| 接口 | 用途 |
| --- | --- |
| GET /v1/realtime | 兼容上游的 Realtime 会话，例如实时音频 |
| GET /v1/responses | Responses WebSocket 交互 |

两者都需要升级连接，但事件和会话规则不同。HTTPS 根地址对应的 WebSocket 地址通常使用 wss://。

## 接入前确认

1. 本站模型和渠道支持所选 WebSocket 协议。
2. 客户端支持该协议的鉴权、初始化和输入事件。
3. 代理及网络允许 WebSocket 升级和持续连接。
4. 应用能够处理增量输出、错误、完成和关闭事件。

HTTP POST /v1/responses 成功，只能证明该 HTTP 路径可用，还需要单独验证 WebSocket。

## 密钥放在哪里

先使用可信服务端客户端验证连接。面向浏览器访客的应用应采用服务端控制的接入方案，不应把长期 API 密钥放入公开前端代码。本指南不假设本站提供临时客户端凭据签发接口。

## 定位连接问题

| 阶段 | 检查方向 |
| --- | --- |
| 401／403 | 凭据、有效期和模型权限 |
| 升级失败 | 协议、代理设置及接口开放情况 |
| 已连接但无输出 | 是否发送了协议要求的初始化与输入事件 |
| 中途断开 | 超时、网络、会话限制及错误事件 |

反馈时提供连接时间、模型、客户端版本和脱敏事件类型，见[联系支持](/docs/support)。
